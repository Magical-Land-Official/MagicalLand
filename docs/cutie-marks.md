# 自绘可爱标志

可爱标志绘制在两侧大腿根的外侧面，画布固定为 12×12 像素。

## 界面

捏脸顶栏的“可爱标志”提供颜色选择、画笔、橡皮、吸色、撤销/重做和水平镜像。一次拖画记为一步，最多保留 64 步；拖出画布会中断连线。左右两侧可独立编辑或共用，重新共用需确认，也可撤销恢复。选择左右侧时自动聚焦对应大腿；关闭自动聚焦后保留当前镜头。

切换预设会保留各自的绘图草稿和历史，退出编辑后释放。预设的新建、复制、改名、删除与保存见[捏马指南](customization-ui.md#预设)。

## 数据与预设

`ModelConfig` 的 `cutieMarkLeft`、`cutieMarkRight` 保存固定 RGBA 字节的 Base64；`cutieMarkLinked` 默认开启。联动时只存左侧数据，右侧字段为空；解锁复制当前共用图，重新锁定采用编辑中的那一侧。字符串不可变，读取画布每次返回新数组，因此预设复制与左右独立编辑不会共享可变像素。

`CutieMarkData` 限定 144 像素、576 字节、768 个 Base64 字符。像素只能完全透明或不透明；透明 RGB 归零，全透明图存为空字符串。仅接收固定尺寸的像素数据，旧预设缺少字段时显示空白。

画笔先修改捏脸草稿，保存后随预设同步，取消则恢复旧外观。模型消息上限为 16384 字符，两张图最多占 1536 字符。服务端转发前和客户端接收后都验证字段类型、编码长度、透明度和规范形式。服务器仅保留在线外观。

## 显示

在身体调色完成后的动态纹理上合成图案，只交给对应大腿骨骼：

- `LHindLeg`：256² 图集 `[88,54]` 到 `[100,66]`，右、下边界不包含。
- `RHindLeg`：`[56,78]` 到 `[68,90]`，右、下边界不包含。

GeckoLib 烘焙结果确认每块覆盖对应骨骼的一张完整外侧面，其他骨骼使用普通身体纹理。图案颜色乘原始身体图的灰度明暗，再接受场景光照；身体调色不会改变图案颜色。橡皮恢复调色后的身体像素。传统乘色模式先完成身体调色，再合成图案。

图案直接合成到纹理，复用原有几何和深度处理。整数倍方形资源包按最近邻放大；比例不符时停用标志绘制。

正式与远程纹理按颜色、侧别和图案缓存，受数量和显存预算限制，资源重载或离线时清理。当前编辑预设使用两个可复用草稿纹理槽，笔画更新原纹理，退出编辑后释放。草稿与已应用外观、其他玩家的缓存相互独立。

## 验证

以下为实现阶段的无窗口测试记录，测试源码在本地维护：

`tests/cutiemark/CutieMarkDataTest.java` 覆盖编解码、透明度、坏输入、镜像、左右联动、预设复制和消息校验接入。

`CutieMarkTextureTest.java` 检查真实 base.png、真实烘焙 UV、两面范围、像素比例、明暗/颜色/透明度，以及纹理隔离和预算守卫。

`CutieMarkDraftTest.java` 使用隔离存档，覆盖草稿、取消、保存重读及复制后独立编辑。实际画笔交互和游戏内外观不在上述测试范围内。
