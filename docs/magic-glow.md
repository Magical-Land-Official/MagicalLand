# 魔法光晕与独角兽角

## 行为

- 玩家启用独角兽角、主手或副手持有物品时，角与悬浮物品使用同一 `magicGlowColor`。远程玩家沿用其同步的模型配置。
- 没有施法状态时，空手不显示角部光晕；Addon 施法和无翼独角兽悬浮可独立亮角。隐藏角、隐身或旁观者不显示角部光晕。
- 角部光晕由三层圆角包络组成，跟随骨骼与 cube 旋转。`horn_aura` shader 控制柔边、根尖淡出及缓慢游动的宽光纹。
- 三层横向增量为 0.22 / 0.70 / 1.18 模型像素，越向外越淡；角本体保持原大小。
- 每 3–4 秒出现 2–4 颗四角星，存在约 0.9 秒，轻微上浮、散开并淡出。它们是按玩家 UUID 和时间计算的装饰光点，不创建独立粒子实体。手持物共用此节奏；2026-09-09 的调整仅提高频率，数量与尺寸不变。
- 角、第一／第三人称悬浮物品、物品拖尾、无翼独角兽包身光及出窍光焰使用同一类宽幅不规则光纹，保留各自的轮廓与柔边。四角星继续作为稀疏装饰。

## 渲染修正

### 2026-09-10：角部光纹

角表面使用游动的宽光纹，明暗调制范围为 0.49–0.895，增强反差并基本保持平均亮度。角周接缝与 12 秒循环连续，颜色、包络、根尖点亮进度和柔边保持原规则。

物品、拖尾和包身光也使用同类纹理；包身光的明暗变化较轻，以保留身体细节。

### 统一光纹与空手光焰

物品原贴图的 alpha 仍负责剪影，流动光纹单独使用模型局部横向／高度坐标，避免跟随图集上的纹理排布。拖尾沿自身宽度和长度计算光纹，保留渐隐、速度长度与惯性；包身光在整只角色的柔边上做缓慢变化，强度预算不增加。

空手出窍改用 `MagicFlame`：约 0.095 格半径的柔光核、外围淡晕和逐渐收尖的焰尾。静止时轻微上扬，移动时向真实位移的反方向延伸，尾长封顶 1.05 格。运动每 tick 采样、渲染只插值；传送、世界切换及断线清理历史。每个光焰最多 36 个顶点、缓存最多 128 个实体，继续交给 `HornAuraPass` 处理深度和云层。

`AppearanceVisuals.renderFlame` 是 API 1.3 的公共入口，Gameplay 通过它复用光效。旧 `renderOrb` 签名保留为静态光焰。核心和拖尾都使用加色 RGB 与独立透明度合成，避免弱光在 Fabulous 的 8 位缓冲中因 alpha 平方而丢失。

光效图层使用专用透明状态，每批明确设置 `SRC_ALPHA / ONE` 的 RGB 混合和 `ONE / ONE_MINUS_SRC_ALPHA` 的 alpha 混合，与 shader 定义保持一致。仅修改 shader JSON 不够：连续绘制不同纹理时，Minecraft 可能命中同一混合缓存而跳过重新设置；原 `LIGHTNING_TRANSPARENCY` 会在第二批把 alpha 改回平方算法。

### 早期兼容图层的深度修正

旧光晕只写颜色，不写深度，且始终使用主帧缓冲。后续图层覆盖或 Fabulous 合成时，无法利用光晕自身深度正确排序。

早期 `magic_glow` 兼容图层保留 `LEQUAL` 深度测试，启用颜色与深度写入；世界渲染使用 `ITEM_ENTITY_TARGET`，第一人称和界面使用主目标。目前实际角光、物品、拖尾和出窍改走 `horn_aura`；这套旧入口没有活跃调用，继续保留兼容。当前柔边光的时序见下节。

物品的原始图层先提交，再绘制光晕，避免光晕写入深度后反而挡住尚未提交的原物品。界面草方块预览也先提交原物品。

专用 `magic_glow` shader 沿用原版 eyes 顶点程序和原有全亮颜色算法，只增加 alpha < 0.1 的透明像素丢弃。不能仅把旧 shader 改为写深度：透明背景也会写入深度，形成看不见的挡板。也不能直接换成实体 emissive 程序，其顶点阶段仍引入方向性明暗。

保留原光晕的颜色、混合状态和两次偏移绘制；新增的有色图层缓存上限为 256，避免拖动颜色滑块时无限累计图层。

角光晕的颜色、时间和星星类型随顶点传递，不使用逐玩家全局 uniform，避免多人缓冲串色或时间错配。时间借用该全亮图层不需要的 overlay 坐标，12 秒周期无缝循环。每层包络 96 个四边形，原几何缓存弱引用。

## 柔边挖掉身体的验收修复

首版在遍历到 Horn 骨骼时就绘制光晕。柔边虽透明却写入了主深度，身体/鬃毛中稍后才提交的表面因此被拒绝，看起来像被光晕挖空。只增加透明像素丢弃阈值不能解决半透明部分；只关深度写入也会让迟绘身体反过来盖掉光晕。

现在 Horn 阶段只保存几何与当帧姿势，`HornAuraPass` 在正确时机统一提交：

- 普通画质世界：云层、天气绘制后的 `LAST`，主目标、`COLOR_MASK + LEQUAL`；避免后方云覆盖前方光效。光晕不覆盖身体深度，前方实体、方块及云仍能遮住光。
- Fabulous 世界：保留透明合成前的 `AFTER_TRANSLUCENT`，使用 `ITEM_ENTITY_TARGET + ALL_MASK + LEQUAL`，交由原版透明合成排序身体、云与光晕。光晕深度只用于透明目标排序；只写颜色会使 `transparency.fsh` 将光晕排到身体后面。
- 捏脸预览：整只模型渲染完成后，先提交其身体、鬃毛和眼部图层，再用主目标 `COLOR_MASK + LEQUAL` 叠加光晕。

队列使用独立缓冲，每帧开始/结束、断开连接清空，最多保存 256 个模型光晕。保存并恢复发射时的 model-view、projection、排序方式及 shader color，不重复乘相机变换，不干扰下一帧或后续界面。星星、物品光晕、拖尾和出窍光焰按同一规则提交。

## 检查与验收

- Java 17 局部类型检查通过。
- `tests/render/MagicFlameTest.java`：实际位移采样、帧率无关插值、传送重置、尾向／长度／预算与多相机矩阵下的几何检查。
- `tests/render/horn-aura-integration/`：真实 `RenderLayer.draw → ShaderProgram.bind` 连续绘制两种纹理，20 项检查包含旧状态失效的负对照、修复后的普通／Fabulous 路径、同一混合缓存命中、RGB 与 GPU 错误。
- `tests/render/HornGlowGeometryTest.java`：以实际 GeckoLib 烘焙后的角验证几何、旋转、局部流动 UV、缓存、稀疏星星频率/数量和确定性；参数为 `mare_geo.json` 路径。
- `tests/render/HornAuraShaderTest.java`：隐藏窗口 GPU 检查实际顶点/片元程序链接、柔边、流动周期、星形透明角落与深度顺序；参数为 Minecraft 客户端 jar 路径、本项目 shader core 目录。
- `tests/render/HornAuraOrderingTest.java`：真实 `transparency.fsh` 与独立浮点帧缓冲的 16 项 GPU 回归；复现旧中途写深度的身体缺失、验证普通模式延后叠加和 Fabulous 正确排序，以及前景遮挡和主深度保持。参数同上。此前的 shader/深度检查没有模拟身体迟绘，这次补齐该场景。
- `tests/render/MagicGlowDepthTest.java`：隐藏 OpenGL 窗口中 9 项 GPU 回归检查，覆盖旧设置的后方覆盖复现、新设置的前后遮挡、透明边缘、深度值和原有颜色保持。需要 LWJGL 依赖；参数为带原版 shader 的 Minecraft 客户端 jar 路径、本项目 `magic_glow.fsh` 路径。
- 上述结果来自局部编译与合成场景，不包含完整构建或 Minecraft 实机验收。
