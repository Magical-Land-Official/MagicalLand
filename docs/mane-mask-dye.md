# 鬃毛与尾巴全区域遮罩分色

2026-09-08：01 前发、后发、尾巴各加入 6 区，共 18 个独立色槽。

2026-09-09：扩展到前发 01–08、后发 01–06/08、尾巴 01–07，共 22 个部件款式，每部件 6 区。后发 07 和尾巴 08 留空。

## 开发者速览

`mane.png` 保存灰度纹理和手绘明暗，各款式 JSON 按 UV 像素指定色区。渲染时用玩家选择的色阶映射原灰度，在原模型上完成挑染并保留发丝纹理。

02–08 的六区沿发束延续：主卷传递全宽色序，碎发继承子区间。源坐标位于 `Resources/ManeDyes/flow-layout.json`，01 使用独立布局。UV 约定和本地生成工具用法见[共享纹理维修](mane-shared-texture-repair.md)。文末验证数字对应各自日期的资源版本。

| 文件/模块 | 职责 |
| --- | --- |
| `mane_dyes/stripe01.json` | 01 的色区形状，1–6 为色区编号 |
| `mane_dyes/style02.json` … `style08.json` | 各自描述对应款式的色区；同一文件只列实际存在的 FRONT / BACK / TAIL |
| `ManeDyeMask` | 校验并展开 JSON 遮罩，兼容旧版编号，按纹理尺寸取样 |
| `ModelConfig` | 保存每部件的 6 色；null 表示锁定跟随该部件主色，并迁移旧配置 |
| `ManeDye` + `ManePalette` / `BodyColorRamp` | 解析主色联动和色区锁，为独立颜色计算阴影/高光，保持原 alpha |
| `ManeTintTextures` | 合成并缓存动态纹理；遮罩身份、部件和色阶共同决定分色缓存，资源重载/退出时回收 |
| `ManePage` / `PonyRenderer` | 折叠式颜色控件；选择部件纹理并跳过旧挑染覆盖骨骼 |

例如后发 4 区设粉色、5 区设紫色，其余色槽为 null：4、5 区使用独立色阶，其余继承后发主色及其明暗。

维护时主要注意：

- 色区形状由遮罩决定，质感由基础贴图决定；用灰度反推色区会把阴影误当挑染。
- 改 UV 后同步对应遮罩。新增发型需同时更新遮罩、注册表和 `ManeDye` 支持范围。
- 不同款式可以复用基础贴图与 UV；它们各自的遮罩和动态纹理独立。同款同部件内完全重叠的 UV 仍只能得到相同颜色，若两处应有不同分区，必须先拆开这项 UV 冲突。
- 锁定色区继承完整色阶，确保手动阴影和高光也与主色连续。
- `Resources` 源贴图/模型与 `src/main/resources` 运行时版本一起维护。Blockbench 保存灰度源图，玩家配色由运行时生成。

独立逻辑测试在本地维护，需 JDK 17+ 和 Gson。取得工具后，可运行 `./tests/mane/run-dye-tests.ps1 -GsonJar 'gson.jar 的绝对路径'`；测试编译到临时目录。

## 使用

在捏脸的“鬃毛”分类中选择前发、后发或尾巴，开启“遮罩分区调色”，再展开主色下的对应分色项。各款式使用自己的六区遮罩，三处部件可独立混搭。

- 每区锁定时跟随本部件主色和完整高光/阴影；解锁保留当时颜色，然后可以独立调整。
- 相邻的 4、5 区可设置为粉、紫，其余区跟随主色，即可手动搭配双带挑染。全部区域解锁后可做多色搭配。
- 每个部件独立保存 6 色，色区锁跟随本部件主色。前后发和尾巴的主色仍可联动。
- 更换款式沿用当前部件的 6 色，色区位置由新款式决定。不同配色组合可保存为角色预设。
- “全部色区跟随本部件主色”将当前部件的 6 色重新锁定；关闭总开关只停用分色，不清空配色。
- 异色色区自动计算明暗；与主色相同的色区复用主色完整色阶。逐色区手动阴影/高光编辑暂不提供。

分区调色默认关闭。迁移旧挑染配置时，前发/尾巴的旧色写入 4、5 区；后发 4 区继承主挑染色、5 区继承副挑染色，其余区跟随主色。

## 01 形状与纹理来源

01 使用维修后的 UV 和灰度纹理，源文件、运行时文件及 Blockbench 副本保持同步。六区分色使用这套资源，形状保存在 JSON 遮罩中。

后发色带参考作者原稿 `Resources/Textures/TS.png`，使用白模化前提交 `3fbe96f39e76c7dd717a7cb00ecb9b9aafdcfbb9` 的旧 UV 恢复位置。将粉/紫像素位置拟合为连续三维分区，上移 1.25 个模型单位，再延展到相邻发片和厚度面。因此色带沿用原稿风格，但覆盖范围经过扩展。

拟合误差 RMS 约 0.211 逻辑 UV 单位，低于半个原图物理像素。按原像素网格栅格化，斜边保留像素台阶。前发和尾巴的 4、5 区合并后等于原挑染范围，其余区覆盖原来的主色部分。

全套 01 的 246 个面、9812 个面内像素均有唯一分区，含 UV 边缘 padding 共 17092 像素。01 的专用 UV 区域独立于其他款式。

## 数据与兼容

遮罩使用 version 3、256×256 像素坐标，尺寸字段为 `texture_width` / `texture_height`。每个 region 包含 `part`、`channel`、`runs`。`part` 为 FRONT / BACK / TAIL；`channel` 为 1–6；每条 run 为 `[y,x0,x1]`，终点 x1 不包含。遮罩外为主色。

`stripe01.json` 的 `preset` 为 `stripe01`，其他文件依次为 `style02` … `style08`。读取时校验身份与已注册部件：07 后发、08 尾巴定义无效；缺少合法部件时，该部件回退普通发色。

配置中的 `maneDyePreset` 保持 `stripe01`，表示分区模式；实际资源由 `ManeDye.maskName(config, part)` 根据部件款式选择。

每份资源限制 18 区、8192 条 run、1024×1024 尺寸和 256 KiB 大小；拒绝非法坐标、重复区域和同部件内重叠。01 仍支持旧 version 1 / 2 资源，旧通道 1 / 2 分别规范化为新色区 4 / 5；新增款式要求 version 3，避免误套旧通道含义。旧版客户端不能读取 version 3，联机双方应使用同版本。

`frontManeDyeColors`、`backManeDyeColors`、`tailDyeColors` 为长度 6 的数组，null 表示跟随主色。仅在缺少数组时，从旧 `maneDyeColor` / `maneDyeAccentColor` 迁移；之后以数组为准。非法颜色改为 null，数组长度规范为 6 项。

保存、复制和联机沿用整对象 JSON。分色缓存键包含实际色阶列表、调色模式、部件和遮罩身份，使共用基础纹理的款式保持分区独立。关闭分色或缺少遮罩时使用普通发色缓存，同色共享。每款遮罩独立缓存和记录失败，资源重载、断线或退出时清理；动态纹理上限为 128 项 / 64 MiB。

源工程保留 `Style01FrontManeHighlight` 作为回退资料，游戏按完整骨骼名跳过它。`Style07FrontManeHighlight` 及其子骨骼 `Style07FrontMane02` 含有效发片，必须保留，不能按 `Highlight` 子串批量删除。
